# F1 — Project Continuity & Decision Control

Status: CANONICAL CONTROL LAYER
Purpose: prevent context drift, silent invention, and accidental promotion of proposals into decisions.

## 1. Decision rules
- CONFIRMED = explicitly decided/approved by Akshat.
- SOURCE-DERIVED = factual material supplied in project sources; preserve faithfully.
- PROPOSED = idea suggested during design; not a requirement until approved.
- PENDING = requires explicit confirmation before implementation.
- LEGACY = exists in earlier AI-generated architecture/code but is not automatically approved.
- REJECTED = explicitly rejected; do not reintroduce.
- Never convert PROPOSED/LEGACY into CONFIRMED silently.
- Never invent historical facts, dates, conversations, preferences, or media.
- Historical monthly reports are authoritative content input for monthly archive work.
- Exact dates/timestamps must be preserved when source data provides them.

## 9. Current Supabase audit findings
Public tables observed:
- chat_imports
- chat_messages
- memories
- memory_media
- test_memory

RLS is enabled on these public tables, BUT current policies allow broad anon/authenticated access with `true` conditions on chat imports/messages and memory media, and public read access on memories/media. This is a security concern for a private archive.

Do NOT silently redesign the access model. Before changing access controls, establish the intended private-access model and then implement it safely.

## 10. Monthly update protocol
When Akshat supplies a month’s historical extraction:
1. Treat supplied extraction as source truth for that month.
2. Preserve exact source facts.
3. Add/validate the month in the canonical archive layer.
4. Update Supabase only from verified historical data.
5. Update UI/experiences from the archive; never invent missing history.
6. Re-check F1 before adding any new treatment or feature.

## 11. Change-control rule
Before every meaningful repo/Supabase change:
- identify the F1 requirement it serves;
- classify the proposed change as CONFIRMED, SOURCE-DERIVED, PROPOSED, PENDING, LEGACY, or REJECTED;
- if it is PROPOSED/PENDING/LEGACY and implementation would materially change experience or architecture, stop and ask Akshat rather than assuming approval.
